# AETHERIUM — Motion System Specification

Дата: 15 ноября 2026  
Версия: 1.0

## 1. Принцип

Motion должен помогать понять интерфейс, показывать иерархию и поддерживать атмосферу исследования. Не использовать анимацию ради постоянного движения.

## 2. Уровни движения

### Tier 0 — базовый
Для reduced motion, слабых устройств и fallback:
- без параллакса;
- без постоянного WebGL;
- статичный фон;
- короткие переходы или отключённые переходы;
- все действия доступны без анимации.

### Tier 1 — лёгкий
- fade/translate для появления блоков;
- короткие hover-состояния;
- раскрытие меню;
- анимация добавления в избранное;
- индикатор прогресса.

### Tier 2 — выразительный
Только desktop/high capability:
- мягкий параллакс Hero;
- процедурное звёздное поле;
- WebGL-сцена с ограниченным DPR;
- переходы космических кадров;
- интерактивные орбитальные элементы.

## 3. Motion tokens

- Micro: 120–180 ms.
- UI transition: 180–280 ms.
- Panel/dialog: 280–420 ms.
- Section reveal: 450–700 ms.
- Easing: cubic-bezier(.2,.8,.2,1) для естественного выхода; без резких пружин по умолчанию.

Не анимировать большие площади и сложные фильтры без необходимости.

## 4. Сценарии

- Hero reveal: один раз при загрузке.
- Navigation drawer: opacity + translate, блокировка фона только когда панель открыта.
- Product card: лёгкий подъём и подсветка рамки; без увеличения, которое ломает сетку.
- Compare: мягкое добавление строки/модели и ясное сообщение об ограничении.
- Favorite: короткая смена состояния с aria-pressed.
- Selector wizard: переход между шагами с сохранением фокуса и объявлением нового шага.
- Dialog: появление и закрытие с корректным возвратом фокуса.
- Scroll reveal: запуск один раз, не анимировать повторно при каждом пересечении.

## 5. Производительность

- Предпочитать transform и opacity.
- Не использовать постоянный blur на больших областях.
- Пауза анимаций вне viewport и при document.hidden.
- Учитывать device capability; не полагаться только на user-agent.
- Ограничить DPR и частоту обновления WebGL.
- Не создавать отдельные бесконечные RAF-циклы для каждого компонента.
- Использовать единый scheduler или нативные CSS-анимации, если они проще.
- Проверять отсутствие layout thrashing.

## 6. Доступность

- Уважать prefers-reduced-motion при первой загрузке и при смене настройки.
- Не передавать смысл только движением.
- Не запускать интенсивную вспышку/мигание.
- Не блокировать прокрутку ради декоративного эффекта.
- Не перехватывать pointer/touch так, чтобы интерфейс становился недоступен.

## 7. Приёмка

Каждая анимация должна иметь описанную цель, триггер, длительность, fallback и поведение при reduced motion. Не добавлять эффект, если его невозможно проверить или он ухудшает удобство.
