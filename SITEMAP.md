# AETHERIUM — Sitemap и UX-архитектура

Дата: 15 ноября 2026  
Версия: 1.0  
Статус: целевая структура для прототипа; коммерческие маршруты активируются после подключения данных и сервисов.

## 1. Принципы архитектуры

- Два равноправных способа выбора: по задаче и по техническим характеристикам.
- Главные коммерческие страницы доступны не глубже 2–3 переходов.
- Информационные материалы связаны с категориями и товарами.
- URL категорий и товаров должны быть самостоятельными и индексируемыми.
- Не создавать пустые страницы под категории, для которых нет контента.
- Не активировать checkout без реальной серверной обработки заказа.

## 3. Страницы и назначение

### Главная /
Задача: быстро объяснить ценность бренда и направить к подбору или каталогу.
Блоки:
- Header и навигация;
- Hero с основным CTA;
- выбор по задаче;
- категории оборудования;
- блок «Как выбрать»;
- подборщик;
- образовательные материалы;
- преимущества, подтверждённые фактами;
- FAQ;
- Footer.

### Каталог /catalog/
Задача: обзор ассортимента и вход в категории.
Функции: поиск, фильтры, сортировка, количество результатов, сброс фильтров.

### Категория /catalog/{category}/
Задача: выбор внутри одной категории.
Блоки: H1, краткое полезное введение, фильтры, сортировка, карточки, FAQ, ссылки на гиды.

### Товар /product/{slug}/
Задача: помочь оценить конкретную модель.
Блоки: галерея, название, SKU, цена/наличие при наличии данных, ключевые характеристики, назначение, ограничения, комплектация, совместимость, документация, похожие товары.

### Подборщик /telescope-selector/
Задача: провести пользователя через короткую серию вопросов.
Результат: несколько подходящих классов/моделей с объяснением критериев и компромиссов.

### Сравнение /compare/
Задача: сопоставить до трёх товаров по одинаковым полям.
Отсутствующие значения показывать как «не указано», не заполнять догадками.

### Избранное /favorites/
Задача: сохранённые товары.
Хранение: localStorage в прототипе; синхронизация между устройствами не обещается.

### Гиды /guides/ и журнал /journal/
Задача: отвечать на вопросы аудитории и формировать органический спрос.
Каждая статья должна иметь автора/редакционный источник, дату обновления при необходимости, оглавление, внутренние ссылки и проверенные технические утверждения.

### О проекте /about/
Задача: рассказать о реальном магазине и команде. До появления фактов не создавать вымышленную историю компании.

### Контакты /delivery/ /payment/
Публиковать только после получения подтверждённых данных.

### Корзина и checkout
В прототипе допускается только интерфейсный макет с ясной маркировкой. Реальное оформление заказа требует backend, расчёта доставки, цен, остатков и безопасной обработки персональных данных.

## 4. Глобальная навигация

Desktop:
- Каталог с раскрывающимися категориями;
- Подбор телескопа;
- Сравнение;
- Журнал;
- О проекте;
- Избранное;
- Поиск.

Mobile:
- компактная шапка;
- выдвижная панель навигации;
- приоритетные быстрые действия;
- удобные фильтры в отдельной панели;
- сохранение контекста при возврате из карточки.

## 5. Каталог: обязательные фильтры

Включать только поля, которые реально заполнены в каталоге:
- оптическая схема;
- апертура;
- фокусное расстояние;
- тип монтировки;
- назначение;
- масса/габариты, если известны;
- система наведения;
- совместимость аксессуаров, если подтверждена.

Не использовать универсальный фильтр «максимальное увеличение» как главный критерий выбора.

## 7. Состояния интерфейса

Для каждой интерактивной функции предусмотреть:
- default;
- hover;
- focus-visible;
- active;
- loading;
- empty;
- error;
- disabled;
- success только при реальном успешном действии.

## 8. URL и SEO

- ЧПУ латиницей, стабильные slug.
- Один canonical URL для каждой индексируемой страницы после утверждения домена.
- Фильтровые комбинации не должны бесконтрольно создавать индексируемые дубли.
- Хлебные крошки отражают реальную иерархию.
- У каждой страницы уникальные title, description и H1.
- Страницы сравнения/избранного и технические состояния — по отдельной SEO-политике, обычно без индексации.
- Sitemap содержит только канонические страницы с полезным контентом.

## 9. Критерии приёмки

- Каждый пункт карты сайта имеет определённый статус: реализовать, отложить или не включать.
- Нет пустых категорий и неработающих маршрутов.
- Навигация доступна с клавиатуры.
- Мобильная навигация не перекрывает критичные действия.
- Пользователь может перейти из статьи в категорию и товар.
- Фильтры используют нормализованные поля каталога.
- Коммерческие маршруты не симулируют реальные заказы.
