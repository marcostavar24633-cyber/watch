# AETHERIUM — Technical Architecture Decision Record

Дата: 15 ноября 2026  
Статус: принято для статического прототипа; пересмотр при появлении требований к backend.

## 1. Контекст

Текущая ветка содержит один большой index.html с встроенными CSS и JS, а в корне не обнаружен package.json. Целевой продукт требует отдельных SEO-страниц и масштабируемого каталога. Требуется избежать неоправданной миграции стека и сохранить совместимость с простой статической публикацией.

## 2. Решение

Для следующей итерации использовать статическую многостраничную архитектуру без сборщика:
- отдельные HTML-страницы с собственным содержимым и метаданными;
- общий CSS в assets/css;
- общий JS в assets/js;
- каталог в JSON;
- общий shell/header/footer через небольшой клиентский модуль либо статически повторяемую семантическую разметку — выбрать один подход и не смешивать хаотично;
- localStorage для избранного и сравнения;
- никаких серверных функций и фиктивного checkout.

Это решение минимизирует новые зависимости и подходит для GitHub Pages/обычного статического хостинга.

## 3. Структура

Предлагаемая:
- index.html
- catalog.html
- product.html (демонстрационный шаблон с query/slug, если не генерируются отдельные документы)
- compare.html
- favorites.html
- selector.html
- journal.html
- guide-optics.html
- about.html
- 404.html
- assets/css/tokens.css
- assets/css/site.css
- assets/js/site-shell.js
- assets/js/catalog.js
- assets/js/product.js
- assets/js/lists.js
- assets/js/selector.js
- assets/data/products.json
- docs/*.md

Для SEO полноценных индексируемых товарных страниц в дальнейшем предпочтительны отдельные HTML URL или генерация статических документов. Клиентская страница product.html?slug=... не должна считаться окончательной SEO-архитектурой для большого каталога.

## 4. Почему сейчас без framework

- Нет существующего package.json и сборочного контура.
- Не подтверждена необходимость серверного рендеринга или сложного состояния.
- Статический сайт остаётся простым в публикации и переносе.
- Для текущего объёма прототипа HTML/CSS/JS достаточно.

Переход на Vite/React/Astro рассматривать, если появится большой каталог, генерация множества товарных страниц, контентная CMS или сложная маршрутизация.

## 5. Ограничения

- JSON fetch требует запуска через HTTP(S), не file://.
- localStorage не синхронизируется между устройствами.
- Нет серверной корзины, заказов, оплаты, авторизации или управления остатками.
- Общие shell-компоненты, вставляемые JS, не должны содержать критичный SEO-контент.
- Все страницы должны иметь работающий fallback при отключённом JS, где это возможно.

## 6. Порядок миграции

1. Создать общие токены и стили.
2. Создать общий shell и базовые интерактивные механики.
3. Создать каталог JSON с демонстрационными записями.
4. Реализовать главную и каталог.
5. Реализовать карточку, сравнение, избранное и подборщик.
6. Добавить журнал/гиды и информационные страницы.
7. Проверить ссылки, доступность, мобильную компоновку и статические сценарии.
8. Сохранить предыдущую реализацию в истории Git; не менять исходную ветку.

## 7. Приёмка

- Нет сборочной зависимости, не отражённой в документации.
- Страницы работают на статическом хостинге.
- SEO-контент находится в HTML, а не только в JS.
- Данные отделены от шаблонов.
- Все коммерческие функции имеют честные статусы.
